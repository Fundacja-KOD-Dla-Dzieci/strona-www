# Contributing - Fundacja Kod dla Dzieci

Dziękujemy za zainteresowanie współpracą z Fundacją Kod dla Dzieci! Ten dokument zawiera wytyczne dotyczące współpracy z naszymi projektami.

## Jak możesz pomóc

### 🧑‍💻 Wolontariat techniczny

#### Programowanie
- **Frontend:** React, Vue.js, HTML/CSS/JavaScript
- **Backend:** Python (Django/Flask), Node.js, PHP
- **Mobile:** React Native, Flutter
- **Embedded:** Arduino, Raspberry Pi, C/C++
- **AI/ML:** Python, TensorFlow, PyTorch

#### Design i UX
- Projektowanie interfejsów dostępnych
- Testowanie użyteczności z użytkownikami końcowymi
- Tworzenie materiałów graficznych
- Dokumentacja wizualna

#### DevOps i infrastruktura
- Konfiguracja serwerów i CI/CD
- Monitoring i bezpieczeństwo
- Automatyzacja procesów

### 🤝 Wolontariat nietechniczny

#### Współpraca z użytkownikami
- Testowanie rozwiązań z dziećmi i rodzicami
- Zbieranie feedbacku od terapeutów
- Dokumentowanie potrzeb użytkowników

#### Promocja i fundraising
- Tworzenie treści marketingowych
- Organizacja wydarzeń
- Nawiązywanie partnerstw

## Proces współpracy

### 1. Pierwszy kontakt
- Napisz na kontakt@fundacjakod.pl
- Opisz swoje umiejętności i zainteresowania
- Dołącz portfolio/GitHub (jeśli masz)

### 2. Onboarding
- Zapoznaj się z misją fundacji
- Przejrzyj dokumentację techniczną
- Dołącz do Discord dla komunikacji

### 3. Wybór projektu
- Przejrzyj [listę projektów](projekty/)
- Wybierz projekt zgodny z Twoimi umiejętnościami
- Skontaktuj się z liderem projektu

### 4. Rozpoczęcie pracy
- Zapoznaj się z dokumentacją projektu
- Skonfiguruj środowisko deweloperskie
- Rozpocznij od prostych zadań

## Standardy pracy

### Kod
- Przestrzegaj [standardów kodowania](dokumentacja/techniczna/standardy/kodowanie.md)
- Pisz czytelny i dobrze udokumentowany kod
- Testuj swoje zmiany przed wysłaniem PR

### Git workflow
- Używaj [Git workflow](dokumentacja/techniczna/standardy/git-workflow.md)
- Twórz branch dla każdego zadania
- Pisz opisowe commity i PR

### Code review
- Wszystkie zmiany przechodzą przez [code review](dokumentacja/techniczna/standardy/code-review.md)
- Bądź konstruktywny w feedbacku
- Ucz się z sugestii innych

## Komunikacja

### Kanały
- **GitHub Issues/PRs:** Dyskusje techniczne
- **Discord:** Komunikacja na bieżąco
- **Email:** Kontakt formalny

### Zasady
- Bądź szanowny i konstruktywny
- Zadawaj pytania - lepiej zapytać niż zgadywać
- Pomagaj innym wolontariuszom
- Dokumentuj swoje decyzje

## Uznanie

### Jak uznajemy wkład
- Wszystkie kontrybucje są wymienione w README projektów
- Regularne podziękowania w sprawozdaniach fundacji
- Możliwość udziału w konferencjach i wydarzeniach
- Certyfikaty wolontariatu

### Portfolio
- Możesz używać projektów fundacji w swoim portfolio
- Zachęcamy do blogowania o doświadczeniach
- Możliwość referencji od fundacji

## Pytania i wsparcie

### Gdzie szukać pomocy
- **Discord:** Najszybsza odpowiedź
- **Email:** kontakt@fundacjakod.pl
- **GitHub Issues:** Problemy techniczne
- **Dokumentacja:** Sprawdź najpierw dokumentację

### Mentoring
- Każdy nowy wolontariusz dostaje mentora
- Regularne spotkania 1:1
- Wsparcie w rozwoju umiejętności

## Bezpieczeństwo

### Zasady bezpieczeństwa
- Przeczytaj [SECURITY.md](SECURITY.md)
- Nie udostępniaj danych wrażliwych
- Zgłaszaj problemy bezpieczeństwa odpowiedzialnie
- Używaj silnych haseł i 2FA

### Dane osobowe
